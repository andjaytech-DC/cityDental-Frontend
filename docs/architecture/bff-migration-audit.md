## 7. Migration phases

### Phase 1 — Auth core (NestJS-owned session)

Move credential verification, JWT signing/verification, tokenVersion revocation, RBAC and the audit of LOGIN/LOGOUT/password-change into a NestJS AuthModule, and add the JwtAuthGuard + PermissionsGuard every later phase needs.

Scope: 4 route(s), 2 server surface(s).

Exit criteria:
- GET /api/v1/auth/me, POST /api/v1/auth/login, POST /api/v1/auth/logout, POST /api/v1/auth/change-password implemented and tested
- apps/web does not verify JWTs itself and does not read the User table for session hydration
- admin-e2e.test.ts route-module imports for auth/* are removed and replaced by NestJS e2e coverage

### Phase 2 — Public booking catalog

Move the unauthenticated patient self-service surface (doctors, locations, availability, book) into NestJS so the booking wizard talks to the API only.

Scope: 4 route(s), 0 server surface(s).

Exit criteria:
- Wizard consumes apiFetch/apiFetchValidated against NEXT_PUBLIC_API_URL
- app/api/doctors, app/api/locations, app/api/appointments/{availability,book} deleted
- Server-side overlap semantics preserved (409 on double booking)

### Phase 3 — Money and messaging

Move payment order/verify/webhook and communications send/history into NestJS modules with the provider abstractions, idempotency and truthful NOT_CONFIGURED behaviour intact.

Scope: 4 route(s), 1 server surface(s).

Exit criteria:
- Webhook stays public and HMAC-verified; payment idempotency preserved
- COMMUNICATIONS_ENABLED=false still sends nothing and reports NOT_CONFIGURED
- app/api/admin/communications and app/api/payments/* deleted

### Phase 4 — Admin read + write APIs

Replace direct Prisma reads in admin Server Components and the writes in server actions with NestJS endpoints consumed by the web app.

Scope: 1 route(s), 18 server surface(s).

Exit criteria:
- Resource controller coverage for patients, doctors, appointments, locations, users, audit log and reports
- apps/web no longer imports @/lib/{patients,admin-doctors,appointments,locations,users,communications}

### Phase 5 — Delete the BFF shell

Remove the residual Next.js data layer and the web-side Prisma dependency so the web app is a pure client of NestJS.

Scope: 0 route(s), 0 server surface(s).

Exit criteria:
- app/api directory removed and no route.ts remains
- apps/web/src/lib/db.ts, audit.ts, payments/ and communications/ removed
- @prisma/client and prisma removed from apps/web/package.json
- node scripts/audit-bff.mjs --strict exits 0
